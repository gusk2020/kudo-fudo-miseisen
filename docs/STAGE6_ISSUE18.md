# Stage 6 / Issue #18 — 琵琶湖・富士山のタッチ操作、地域発展、湖上フェリー、政策ボタン

## 1. 琵琶湖・富士山
- **操作**: 「富士山・琵琶湖を動かす」ツールで、1本指ドラッグ=移動、2本指ピンチ=拡大縮小、2本指ツイスト=回転(`src/ui/gestures.ts` の `multiBegin/Move/End`)。選んだ対象には黄色の枠・中心の丸・回転の印が出る(置けない姿勢の間は赤)。ほかのツールや「表示」では、2本指は従来どおり地図のズーム。指を離すと確定(1回=Undo 1手)、置けない場所なら元に戻して理由を表示。数値ボタン(縮小/拡大・高さ±)は補助として残す。
- **上限**: 大きさ 0.2〜5倍(以前は0.5〜2)。標準の下限は0.5倍で、それより小さくできるのは小さな陸地(面積4000km²以下、沖縄本島など)だけ。標高(手動)の上限は据え置き 0.5〜1.3倍。
- **富士山の標高**: 大きさをタッチ/ボタンで変えると `auto` が付き、標高=1+(大きさ−1)/2(=大きさの半分の割合)、大きさ5倍で標高3倍(上限3倍。0.2倍→0.6倍、0.5倍→0.75倍)。手で決める標高(`height`、0.5〜1.3倍)は別の値で範囲も別、設定されていればそちらが優先。`auto` が無い既存セーブは従来どおり(標高は変わらない)。
- **配置判定** (`featureHost`): ①中心(アンカー)が陸地の上 ②輪郭全体(面積1.2倍)が**同じ陸地**に収まり、海岸線から1km以上 ③2つが重ならない。県境は判定に使わない。海・別の島へのはみ出しや湖が岸に接することは拒否。海岸線は動かない。
- **地形**: 編集後の富士山は、実データ(DEM)の元の山体を周囲の高さまでならしてから新しい山を載せる。湖は新しい位置だけが水になる(旧位置は陸に戻る)。経路探索・建設費は生成後の標高から計算されるので自動で反映。
- **保存**: `FeatureState.auto`(任意項目)を追加。無いセーブは従来どおり。地図ハッシュは変えていない。
- **既知**: 沖縄の県庁所在地の座標(`prefPoint`)は実座標で、ゲーム内の沖縄本島(圧縮した形)とずれている(既存の挙動。本件では変更せず)。

## 2. 地域発展(`src/sim/sites.ts`)
首都・副首都は商業・産業・工業・観光すべてにプラス、皇居・富士山・琵琶湖は観光にプラス。効果は**地図から毎回読む**ので、移動後は新しい場所にだけ働き、旧位置に残らない。強さ=重み×到達度(同じ府県は0.7、周辺は exp(−距離/90km) の大きい方)。
| 区分 | 既存経済モデルとの対応 |
| --- | --- |
| 商業 | 都市の旅客の引力(重力モデルの質量)×(1+商業+観光) |
| 産業 | 都市の産業水準の目標値(`industry`)+0.5×産業、人口増加率にも小さく加算 |
| 工業 | 貨物の発生量(`pop×industry×(1+工業)`)、道路/鉄道の貨物競争に効く |
| 観光 | 旅客引力に加算+周辺集落の人口減少を緩める |
産業と工業は貨物で重なるが、産業=ゆっくり変わる水準、工業=一度に出る量、で役割を分けた。地域予算配分(`regionShare`)にも反映。数値は暫定(合成)。

## 3. 琵琶湖フェリー(`src/sim/ferry.ts`)
湖は海ではない(同じ陸地の湖岸の港を結ぶ。海峡の橋/トンネル計画の対象外)。港は湖岸のセルで、既存の道路ノードか、なければ地方道で道路網につなぐ。長軸の航路は1950年から、短軸の横断航路は1965年以降に長い航路が混み(負荷50%以上)・道路建設の意欲があり・港の整備費が予算の2%以下のとき新設。使われない航路は通常の辺の見直しで廃止。湖を動かす/大きさを変える→ゲーム開始時に新しい湖から港と航路を再計算(開始後は地形が固定)。

## 4. 政策介入画面
「選択しない」と「点を使わず決定」は別機能(前者=何も採用せず持ち点を全額繰越/後者=分野を選んで環境評価で採用、点0)。依頼どおり**前者の機能を「点を使わず決定」の名前で政治・経済・世論の横の位置に1つだけ**残し、重複ボタン(`pol-skip`)を削除。持ち点の繰越は維持。「分野を選び点0で決定」は、分野を選んで「この選択にする」(配分0)で引き続き可能。

## 5. 性能
`analyze`(年次の需要解析)を6都市ごとに時間を譲る生成器(`analyzeGen`)に分割し、1回の `pump` の最大ブロックを短縮。

## 6. 監査(ChatGPT)への対応
- **富士山の自動標高の上限**: 2倍→3倍(`FUJI_AUTO_HEIGHT_MAX`)。式は `1+(大きさ−1)/2`。手動標高の入力範囲(0.5〜1.3倍)は変更なし。
- **沖縄のずれ**: 原因は地図データ。`src/data/japan.json` の那覇市と沖縄県の代表点が (-1188.6,-1400.4)(経緯度で東経123.8°・北緯24.3°、石垣島付近)で、実際の那覇(127.68°E 26.21°N → (-839,-1193))とも、ゲーム内の沖縄本島(x -843〜-780, y -1207〜-1118)とも合っていなかった。地形生成が都市を最寄りの陸セルに自動で移していたので都市は正しい所に出ていたが、首都/副首都/皇居の既定点(`prefPoint`)は生データを使うため海上を指していた。両方を、生成が実際に置いていたセル中心 (-837.5,-1202.5) に直した。**生成される世界は完全に同じ**(地形ハッシュ・那覇のセル3105・沖縄の46セルとも変更前後で一致)なので、既存セーブへの影響はない。

## 7. Issue #20(Pixel 7a実機報告)への対応
- **「不正1件」で「地形を生成中…」のまま止まる**: 原因は回転ボタン(⟲/⟳5°)など一部の操作が配置検証なしで確定していたこと。不正な地図は地形生成が拒否するため、生成待ちの表示が残っていた。対策: (1) 地形編集の確定(`commitEdit`)はすべて、試しに適用して検証し、新しい不正が出るなら**確定しない**(操作前の状態のまま、Undo履歴にも積まない、セーブにも書かない)。(2) すでに不正な配置で保存されたセーブは、読み込み時に該当する湖/山だけを本来の位置に戻す(他の内容はそのまま)。(3) 地形生成の「生成中」状態は世代番号つきの finally で必ず解除。(4) 不正が残る場合は「生成中」ではなく理由を表示。
- **地形編集メニューの小型化**: 元号・首都・副首都・皇居は「⚙ 元号・首都」シートへ移動。地形編集は1行のツール(琵琶湖/富士山/北の山脈/南の山脈/山脈の点)と、対象を選んだときだけ出る回転・大きさの行、アルプス/消す/↶/↷の行だけ。
- **府県の並び**: 首都・副首都・皇居の選択肢は北から南(各県庁所在地の緯度順、`PREF_IDS_NS`)。北海道3県が先頭、沖縄が最後。
- **ツールの解除**: 琵琶湖・富士山の選択はツールそのものになり、選択中をもう一度押すと解除して通常の地図操作に戻る。山脈・皇居・国道1号・なぜ?・風景JSONのツールも同じ(再押下で解除)。政策画面の分野ボタンも再押下で選択解除。回転・拡大・元に戻す等の単発ボタンは従来どおり。
