# Issue #7: Pixel 7a / Chrome の停止・再読み込み — 調査と修正

実機での再現はできないため、CPUを6倍に絞ったChromium(Playwright+CDP `Emulation.setCPUThrottlingRate`)で「起動→地図確定→開通→×20を60秒→40年早送り→保存→道路タップ」を計測した（`tests/e2e/perf.spec.ts`、CI対象外。`PERF=1 CPU=6 npx playwright test perf.spec`）。

## 原因（計測で確認したもの）
| # | 原因 | 証拠（CPU×6、修正前） |
|---|---|---|
| 1 | **道路レイヤーの再描画ごとの描画オブジェクトのリーク** | `Graphics`/`Text` を毎回生成・破棄すると、GC後でも1回あたり約0.13MB残る（100回で+13MB）。×20では毎秒数回再描画され、**JSヒープが +9.5MB/秒（83MB→649MB/60秒）**。数分でタブがメモリ不足になり「再表示」に至る最有力原因 |
| 2 | **シミュレーションが主スレッドを長時間占有** | ×20の60秒間、長タスク130本・合計59.9秒（ほぼ100%占有）、最大1.2秒。1年分の更新がまとめて走る |
| 3 | **開通の儀での初期網生成が1本の長タスク** | `createSim` が **5.4秒** 連続で主スレッドを止める（Chromeの「応答なし」表示の条件に近い） |
| 4 | 道路タップ | 1.1秒（上の混雑の影響） |

切り分けで否定したもの: シミュレーション自体のメモリ（GC後 79→80→79MB で一定）、保存（JSON 0.62MB・約45ms）、地形生成（Workerで実行）。

## 修正
1. **描画の再利用**: 道路レイヤーの `Graphics` と標識の `Text` を一度だけ作って `clear()` で使い回す（標識は最大60個のプール）。再描画頻度を約2Hzに制限（以前は月ごと）。`antialias` を無効化（解像度は最大2倍のまま）。
2. **時間分割実行**: 1か月の更新を短い「アトム」のジェネレーターに分割（`stepMonthGen`）。`SimRunner.pump(8ms)` が1フレームに約8ms分だけ進める。遅い端末では時計が遅れ（HUDに「速度を自動で落としています」）、要求の滞留は24か月で打ち切り。操作列は一括実行と同一なので決定論は不変（単体テストで同一ハッシュを確認）。
3. **初期網生成の分割**: `createSimGen` を10msずつ実行し進捗%を表示。
4. **保存の安全化**: 保存は月の境界でのみ（実行中なら80ms後に再試行。ページを離れる時だけ月を完了させてから保存）。
5. **異常終了からの復帰**: 起動中は `localStorage` に目印を置き、`pagehide`/非表示で消す。目印が残っていた＝前回強制終了と判断し**安全モード**（停止状態・追いつき計算なし）で再開。セーブは保持。
6. **WebGLコンテキスト喪失**: `webglcontextlost` を受けて通知、復帰で再描画。
7. 追いつき計算も `SimRunner` 経由（12msずつ、進捗表示）。

## 効果（CPU×6、修正後）
| 指標 | 修正前 | 修正後 |
|---|---|---|
| 開通の儀の最長タスク | 5,419ms | **515ms**（進捗表示つき） |
| ×20 60秒の最長タスク | 1,246ms | **276ms** |
| ×20 60秒の主スレッド占有 | 59.9秒(100%) | **17.8秒(30%)** |
| ×20 60秒の進行 | 248か月（占有しきり） | 228か月(約×19・操作可能) |
| JSヒープ | 83→649MB（+9.5MB/秒、増え続ける） | **90→103〜192MB（増減して安定）** |
| 道路タップ | 1,093ms | 244ms |

## 未確認
