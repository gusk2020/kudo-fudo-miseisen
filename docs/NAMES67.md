# 昇格都市の名前表示とタップ詳細（Issue #67、ユーザー確定: 「拡大時に表示＋都市をタップして詳細確認」）

branch `claude/ui-promoted-names`（base `claude/issue67-stage2` = PR #71）。鉄道計画の変更（PR #73）は**含まない**。

## 仕様と実装
- **名前**: Stage 23 の既存規則（階層が有効なとき名前を付けるのは首都・政令指定都市・政令特区だけ）は変えない。昇格都市（`sim.oldCities40`）は、**ズーム 2 以上**（`PROMOTED_NAME_ZOOM`、`cityNames.ts`）で (1) 必ず円を持ち（`cityCircles.ts`）、(2) 名前の候補になる（`roads.ts`）。名前の配置順は首都・政令指定都市・政令特区・既存の名前付き、その後に昇格都市を人口順。配置は既存の `placeNames`: 円や既に置いた名前や下地の県庁所在地名に重ならない側（右・左・上・下）が空いていれば置き、なければ**省く**（円は残る）。全体の上限は既存の 45 件（ズーム2以上）。ズーム 2 未満は従来どおり。つまり密集地では全ラベルを出さず、優先度と空きで決まる。
- **タップ**: `gestures.ts` に「短く動かない一本指の接触」の検出を追加（10 CSS px 以内・500 ms 以内、二本指・キャンセル・編集ツールが取った接触は除く）。既存のパン・ピンチ・編集は変えていない（接触の流れは同じで、最後に `tap` を呼ぶだけ）。`app.ts mapTap`: 実ゲームの画面で、編集ツールも遷都のパネルもシートも出ていないときだけ、直近に描かれた円（`roads.drawnCircles`）のうち、指に最も近い円（半径と 22px の大きい方=直径44px以上の的）を選ぶ。何もなければ詳細カードを閉じる。
- **詳細カード**（`cityCard.ts`、画面の下、ドックの上）: 都市名（首都・副首都・政令指定都市・政令特区の別）、所属府県、人口、20年の人口の動き（全国平均との比）、成り立ち（昇格都市は「旧市町村から○年に都市へ昇格(ゲーム上の昇格。史実ではない)」）、交通（道路・鉄道・渡船・港・空港）。既存データだけを読み、保存形式は変えていない。閉じるボタン 44×44px、空の地図をタップ、シートを開く、のいずれかで閉じる。ドラッグ・ピンチではカードは閉じない。

## 検証
- 単体 `tap67.test.ts`（5件）: タップの成立・不成立（動きすぎ・長押し・二本指・キャンセル・編集ツールが取った接触）、カードの内容。
- E2E `names67.spec.ts`（Chromium の Pixel 7 エミュレーション 412×915 のタッチと、PC 1280×800 のマウス。**Pixel 7a 実機ではない**）: 昇格12件の1800年開始ゲームを2000年まで進め、(1) ズーム10で6都市すべてに円と名前がある、(2) 東京周辺ズーム2.5で都市名の重なり 0・45件以下（昇格都市の名前が1〜2件含まれる）、(3) 本物のタップでカードが開き、内容・画面内・ドックと重ならない・閉じるボタン44px、(4) カードを開いたままピンチ（またはホイール）・ドラッグが効き、ドラッグでは閉じない、(5) 閉じるボタンと空の地図のタップで閉じる、(6) シートを開くとカードが消えシートが出る。両方合格。
- `mobile67.spec.ts`（スマホ幅の総合: 全ラベルの重なり・操作部品・ピンチ・ドラッグ・保存→再読み込み→読込）。**道路レイヤーの名前を含めて数え直した**（初版は下地の名前だけ数えていた誤り）: 昇格都市の周りと東京周辺の13視点すべてで重なり 0、名前の高さ 17 CSS px、画面の左右の端で一部切れる名前は最大4件（端にかかる名前）。ズーム2.5では昇格都市の名前が優先度と空きの都合で出ない都市がある（座間市・新座市・東大和市）が、ズーム6と10では全て出る。操作部品は覆われ・画面外なし。

## 既知の限界
- 名前は12px・島名等は10〜11px のまま（既存設計）。Pixel 7a の実機の読みやすさは未確認。
- カードは都市の円をタップしたときだけ。路線・港・空港のタップ詳細は別の機能（台帳）のまま。
- ズーム2.5の密集地では、昇格都市の名前が出ない場合がある（既存の名前配置の優先度）。

## Pixel 7a 実機報告への対応: 「都市の円をタップすると開く場合と開かない場合がある。県庁所在地が開きにくい」
### 再現（修正前、Chromium の Pixel 7 エミュレーション 412×915 のタッチ、`tests/e2e/tap67.spec.ts`）
首都・副首都・県庁所在地（大・中・小）・政令指定都市・一般都市・昇格都市を、画面の中央に置き、ズーム 1.2 / 2.5 / 6 で**本物のタップ**を打った（54回）。**12回が開かなかった**: 小さな県庁所在地（福井市・根室市・豊原）の全ズームと、円を持たない一般都市（いわき市）。開いた全件は「道路レイヤーの円として描画された都市」、開かなかった全件は「描画された円に含まれない都市」（最寄りの円まで 104〜2692 px）。モードによる拒否（編集・遷都・シート）は全件で偽。
### 原因（確定したもの）
当たり判定は `roads.drawnCircles`（道路レイヤーの経済の円）だけを見ていた。県庁所在地は、**地図の下地が描く黄色い小さな点（半径 3.2px、49都市すべて）**が目印で、経済の円になるのは人口の大きい一部だけ（常に出る首都・副首都・上位10都市圏の核、人口上位 N 都市など）。小さな県庁所在地は目印があるのにタップできなかった。大きな県庁所在地（東京・名古屋・神戸・長崎・高松）は円があるので開いた——これが「開く場合と開かない場合がある、県庁所在地が開きにくい」という報告と一致する。
### 修正（最小）
`app.ts mapTap`: 当たり判定の候補に、下地の県庁所在地の点（`w.cities` の `kind === "capital"`）を加えた。最寄りの目印を、その半径と 22 px の大きい方の範囲内で選ぶ。円も点もある県庁所在地は1候補（円の半径と20年の動きを使う）。詳細カードの内容は円がない県庁所在地では「20年の人口」の行が出ない（その値は円の描画時にしか計算していない）。
### 修正後（同じ検査）
66回（目印のある都市の全件）が正しいカードを開いた（Pixel 7 サイズのタッチと PC 幅のマウスの両方）。さらに状況別: **時間が進行中**（速度×1）・**ピンチ直後**（250ms 後）で首都クラスと小さな県庁所在地が開く／**シートを開いている間は開かない**（意図どおり）／**円が重なる場所**（川越市と上福岡市など、中心が 5〜6px しか離れていない3組）で、**タップした円の中心を打てばその都市が開く**。ドラッグ・ピンチがタップにならない回帰は、単体テスト（`tap67.test.ts`）と `names67`（ドラッグでカードが閉じない／開いたままピンチが効く）で引き続き合格。
### 確定していないこと・限界
- 実機（Pixel 7a）での再確認は**未実施**。この修正が報告の原因の全てかは、実機で確かめるまで断定しない。他の原因（例えば、指の動きで10px のずれを超えるとタップにならない）は、エミュレーションでは再現していない。
- **円も黄色い点も持たない都市（人口の大きい一般都市でも、円の選抜から漏れたもの。例: いわき市・壱岐市・対馬市）は、地図に目印がないのでタップの対象にならない**（既存の円の選び方の仕様。名前も出ない）。円の選抜を変えるかは別の仕様判断で、今回は変えていない。
- 点の当たり判定の半径は 22 px（直径 44 px の的）。目印が近接している場所では、最寄りの目印が選ばれる（円どうしの重なりは上の検証のとおり。点と別の都市の円が重なる場所は個別には検証していない）。
