# Stage 11 — 道路図/地形図、山脈の編集の統一、縦横比、役割交換の強化、建設障壁、海峡架橋 (Issue #28)

## 1. 地図の表示と編集UI
- **道路図/地形図**: 設定シート(⚙ 元号・首都)の「地図の表示」で、最初に選べる。選んだ地図はゲームと一緒に保存される(`bg`。地図のハッシュには入らない)。
  - 既定は道路図。地形図は標高と山脈を表示する。
  - 古いセーブには `bg` がなく、これまでの保存先(ブラウザの設定)で動く。
- **道路図では山脈を描かない**: 山脈の線・端点・選択の強調は、地形図のときだけ描く。建設の障壁は内部の計算に残る。
  - 山脈の道具(北・南・点・区間)を道路図で選ぶと、編集の間だけ自動で地形図になり、道具を閉じると道路図に戻る。
- **道路と山脈の編集の統一**: どちらも同じ3つの操作で、Undo/Redoの1手になる。

| 操作 | 国道1号 | 山脈 |
|---|---|---|
| 描く(継ぎ足し) | 描く | 北・南(線の端から描くと続き、別の場所なら新しい線) |
| 点を動かす | 点を動かす | 点 |
| 区間を選ぶ・消す・描き直す | 区間を選ぶ | **区間**(新設。線をタップして選び、「消す」「描き直す」) |

  - 山脈の描き直しは、選んだ線を置き換える。端が元の端の近くなら、そこにつながる。
- コンパクトなUI: 山脈の行に「区間」の1ボタンを足しただけ(Pixel 7aの幅に収まる。E2Eで確認)。縦横の2行目はサイズ表示のタップで開く。

## 2. 琵琶湖・富士山の縦と横
- 縦と横の倍率を別々に変えられる(各 0.2〜5倍)。回転は維持される。
  - 形は「固定の外形 → 山体/湖の自分の座標軸で(横, 縦)に伸ばす → 回転」の順に作る。軸に沿った拡大だけなので、斜めのせん断は起きない(単体テストで、外形が回転×対角行列と一致することを確認)。
  - サイズ表示(例「×1」)をタップして開く「横−/横＋/縦−/縦＋」(その軸だけ)と、従来の「−/＋」(両方一緒)。閉じた状態のメニューは1行のまま。2本指のつまみは両軸を同じ比で変える。
- **富士山の標高との連動の定義**: 面積相当の倍率 `eq = sqrt(横×縦)` を使い、`高さ倍率 = 1 + (eq − 1) / 2`、上限3倍。
  - 縦横が同じなら従来の式と同じ。手で設定した高さは常に優先する。
- 山体の裾野は、伸ばした形のまま(楕円の円錐)に作る。琵琶湖は伸ばした外形で湖面を作る。岸・フェリー・湖上橋は湖面から決まるので、そのまま連動する。
- 互換:
  - 古いセーブには `scaleY` がなく、縦横が同じ(従来の `scale`)。
  - 縦横が同じ大きさの地形のハッシュは、以前と同じビット列(既定・島あり・富士の拡大・移動・琵琶湖の拡大の5通りで確認)。
  - 置けない形はこれまでと同じ地図の検査で拒否され、直前の状態に戻る。

## 3. 首都・副首都の役割交換の強化
- 再調査: 地名による優遇は、Stage 10で既に除いてある(`roles.ts`)。残っていたのは、**首都圏・副首都圏が3府県だけ**だったこと。
  - 実在の関東・近畿は、周りの数府県と一体の都市圏なので、圏の大きさを **5府県** に広げた(`METRO_SIZE`)。
  - 実在の東京から近い順の5府県(神奈川・埼玉・千葉・茨城・山梨)の役割の大きさが、選んだ首都に近い順の5府県へ、近い順どうしで移る。
  - 首都圏と副首都圏は重ならず、首都・副首都の府県は動かさない。全国の総量は変わらない(全組合せで単体テスト)。

## 4. 山脈・富士山の建設障壁
- 原因: 山脈の障壁は、描いた山脈の近さ(`ridge`)だけで決まっていた。
  - 最良のトンネル技術(2050年ごろ)で障壁が元の15%まで下がり、描いた山脈もほぼ無料で越えられた。
  - 移動・拡大した富士山には障壁がなかった。
- 変更(`world.ts`, `terrain.ts`):
  1. **障壁の下限**: 工法がどれだけ進んでも、障壁は少なくとも40%(`MTN_EASE_FLOOR`)残る(旧: 15%)。
  2. **勾配**: 障壁の中では、費用に `(1 + 勾配% / 8)` を掛ける(急斜面ほど極めて高い)。
  3. **富士山の裾野**: 移動・拡大・高さを変えた富士山は、円錐全体を障壁として扱う(`terrain.barrier`)。山頂が1、裾野に向けて標高に比例して下がる(1,500mで1)。
     - 手を加えていない富士山は障壁にしない。実在の東海道は裾野を通る。
     - 川の流れに使う `ridge` と地形のハッシュは変えていない。
  4. 道路・高速道路・鉄道・新幹線・リニアは、すべて同じ経路探索と工費の式を通るので、まとめて適用される。リニアは既存の新幹線の経路に重なる。
  5. トンネルの長さの制限(技術の年代)、岩盤の確率、鉄道が1,300mを超える峠を越えられないことは、これまでどおり効く。
- 定量検証:

**(a) 経路探索(決定的。東京→名古屋、北の山脈を東海道に描いたとき)**

| | 道路の経路 | 鉄道の経路 | 工費の倍率(経路全体) |
|---|---|---|---|
| Stage 10: 1960年 | 325km(迂回) | 335km | 1.00 |
| Stage 10: 1990年以降 | 235km(**山脈を横断**) | 330km | **1.66** |
| Stage 11: 全年 | **315〜325km(迂回)** | 330〜335km | 1.00(障壁の外) |

  - 山脈なしの経路は 235km。Stage 10 ではトンネル技術が進むと道路が山脈を横切ったが、Stage 11 ではどの年も迂回する(+34〜38%)。

**(b) 1950〜2100の通しの計算(両アルプスを除去 → 北の山脈あり。3つのseed)**

| 版 | 東京〜名古屋 1970年 | 同 1990年 | 2050年までの建設費 |
|---|---|---|---|
| Stage 10 | 平均 +77% | 平均 +118% | 平均 +21% |
| Stage 11 | +64% | **+156%** | +13% |

  - 山脈を越える所要時間は、1990年で +156% と、より大きくなった(seedにより +22%〜+360%。平均は +156%)。
  - 建設費の増加が小さいのは、障壁を避けて建てなくなったため(迂回する・越える路線を後に回す)。
  - 未成線(未成)の数は両版とも同程度で(2050年に5〜7本)、山脈だけでは増えなかった。山脈の影響は、迂回と時期の遅れとして現れる。

**(c) 富士山を名古屋〜大阪の間(経度137.0°・緯度35.0°、2倍)に移動**

| | 名古屋→大阪の経路 | 工費の倍率 |
|---|---|---|
| 動かさない | 160km | 1.00 |
| 動かした(Stage 10) | 165km(道路)・170km(鉄道)(裾野に障壁なし) | 1.00 |

## 5. 海峡架橋
### 原因(計測した)
1. **候補が1つだけ**: 計画は「陸地の組ごとに、いちばん近い2都市の1本」しか見ていなかった。本州〜四国の候補は徳島〜和歌山だけで、岡山〜高松、広島〜松山、徳島〜神戸、大分〜松山は、そもそも対象外だった。
2. **橋が選ばれない**: 橋とトンネルのうち安いほうを選んでいた。トンネルのほうが安いか、橋が渡せない長さのうちに技術が先に来るので、橋は計画されなかった(史実の橋は年表に決め打ちで入れた2〜3本だけ)。
3. **距離の測り方**: 候補の都市間の直線距離で費用を見ていた。津軽海峡は都市間が104kmでも海峡は25kmほど。

### 変更(`crossing.ts`, `ferry.ts`)
- **フェリー航路ごとに候補にする**: 陸地を隔てた開通中のフェリー(旅客・貨物、道路・鉄道)が、それぞれ候補。両岸の海岸線の最短(`localGapKm`)を海峡の幅にする。
  - すでに近くに橋・トンネルがある(両端から40km以内)航路は除く。
  - 同時に進めるのは道路・鉄道それぞれ最大2件(旧1件)。
- **橋を優先**: 橋が渡せる幅なら、トンネルの2.2倍までの費用で橋を選ぶ。
  - 橋が近い将来(技術時計で30年先)に渡せる幅なら、トンネルにせず待つ。
  - 40kmを超える海は計画しない(フェリーのまま)。
- **必要な交通量は幅に比例**: 閾値は `0.3 + 幅/60`(10km: 0.47、25km: 0.72、40km: 0.97)。
- **瀬戸内海の鉄道連絡船**: 両端に鉄道がある100km以内の組に、鉄道連絡船を足した(鉄道の橋・トンネルの候補になる)。
- 技術の加速2倍、費用・時間の半減は変えていない。
- 時代・距離・需要・費用の条件は、これまでどおり(人口は幅1kmあたり3,500人、月の工費が国の予算の60%以内)。

## 6. 互換性・性能
- 新しい項目はすべて省略可能: `scaleY`、`bg`、`barrier`(地形の計算結果。保存しない)。古いセーブは作成時のまま読める。
- 地形のハッシュは、縦横が同じ設定のとき以前と同じ。
- Stage 10 の旧仕様のうち、意図して変えた単体テスト:
  - 海峡計画の同時進行数: 1件 → 最大2件(`MAX_ACTIVE_PER_MODE`。上限を超えないことは同じ強さで検査)。
  - 「倍の技術が最初のリンクを遅くしない」: 橋を待つため最初の1本が1〜2年遅れることがある。代わりに「2000年までの完成数が少なくない」ことと、最初のリンクの遅れが3年以内であることを検査。
