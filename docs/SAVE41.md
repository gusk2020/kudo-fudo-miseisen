# Stage 41: 保存・読込の安全性（エラーA・B、判断直前のセーブ）

branch `claude/s41-save-safety`（base `claude/fix-city-tap` = PR #75。PR #76）。鉄道案V2（PR #73）は含まない。

## エラーA: `route number duplicated: national:JP:0`（現行版で保存した手動スロット①が読めない）
- **再現**: `tests/unit/save41.test.ts`。1800年開始のゲームで、1900年と2000年に国道0号を引く（`performRoad0` を2回）と、`sanitizeSim` が `道路網の整合性エラー: route number duplicated: national:JP:0` を返す。Pixel 7a の報告と同じ文。
- **原因**: 遷都のたびに国道0号が作られ、2本目以降は**年（`gen`）で区別される別の路線**になる設計（`ceremony.ts`、Stage 25）。整合性検査（`network.ts checkIntegrity`）は `等級:範囲:番号` だけで重複を判定していた。1800年開始のゲームは100年ごとに遷都するので、2本目の0号は100年遊べば出る（以前は2200年以降の話だった）。
- **修正**: 重複の鍵に `gen` を含めた。同じ番号・同じ年が2本ある**本当の重複は引き続き拒否**（テスト済み）。検査は無効化していない。
- **既存セーブの修復**（`repairRoad0Years`、`save2.ts`）: 後の0号に年が付いていない保存は、その路線自身の履歴（最初の記録の月）から年を求めて `国道0号(年)` と名付ける。最初の（最も古い）0号はそのまま。路線は1本も消さない。保存された原本の文字列には触れない（メモリ上だけ）。年が分からない・同じ年が重なる場合は直さず、従来どおり拒否。
- 未確認: ユーザーの実際の保存データでは試していない（手元にない）。同じ文のエラーを再現して直しただけで、実データの内容が再現と同じ形かは、実機で読み込めるかで確かめる必要がある。

## エラーB: `地形が保存時と一致しません(地形ハッシュ不一致)`（旧バージョンの手動スロット②）
- 地形ハッシュは `generateTerrain` の結果（標高・県・陸・境界線・河川線）のハッシュ。保存は `terrainHash` を持ち、読込時に現在の地形と比べる。
- **測定**（公開されていた Stage 31〜35 版 `ce0327b` と現在の同じ既定の地図、`tests/unit/simhelp.ts realWorld`、旧版の作業ツリーで同じテストを走らせて比較）:
  | | 旧（ce0327b） | 現在 |
  |---|---|---|
  | 島なし: 格子 | x0=-885, y0=-1250, 344×447 | **同じ** |
  | 島なし: 県の数 | 49 | **50**（樺太県）。県の配列のハッシュが違う（旧 671145ed／新 8711c135）、境界線 5124→5128 |
  | 島あり: 格子 | x0=-1280, y0=-1450, 454×**487** | 454×**586**（行が増えた＝南樺太と北部千島を載せたため） |
  | 島あり: 陸セル | 15406 | 17031 |
  | 島あり: 旧範囲（先頭 454×487 セル）の陸・島・県 | — | **一致** |
  | 島あり: 旧範囲の標高 | 698d2cdd | **7b2c121d（一致しない）** |
  | 島あり: 河川線 | 1610 | 1640 |
- **結論**: 旧格子は新格子の先頭部分（行が足されただけ）で、セル番号は同じ地点を指す。しかし旧範囲の標高は一致せず（暫定標高の範囲が変わった）、河川線も変わっている。**旧保存の地形は新しい地形と同一とは言えない**ので、検査が拒否するのは正しい。ハッシュ検証を外して復元することは、誤った地面の上へ道路を戻すことになるため行わない（禁止事項）。
- **検討して採らなかった案**: (1) 旧ハッシュを新しい配列から再構成して比べる → 河川線は新しい範囲の線が途中に混ざり、旧版の配列を再現できない。(2) 旧世代の生成処理を残す → 生成処理の版管理（島のデータの版 `isl20/22/36` に近い仕組み）を地形全体へ広げる大きな作業で、旧版の全データの保存が要る。(3) セル番号が同じであることを使って、旧保存の道路が新地形でも陸・同じ県の上にあるかだけを検査して復元する → 標高が違うため勾配・工事費の記録（`maxGradePct` など）が現地形と食い違う。安全と言える基準を決める仕様判断が要る。
- **やったこと**: 拒否のとき、道路データは別キー（`:quarantine`）へ退避され、保存の上書きはロックされ（`saveLocked`）、元の保存は消えない（以前からの動作）。表示が「地形ハッシュ不一致」だけで原因が分からなかったので、**保存の版の印（`isl36`）から原因を分類して説明する**ようにした（`explainTerrainMismatch`）: 樺太を加える前（Stage 36より前）の保存なら、その旨と「元の保存は消えていない」ことを出す。
- 未確認: ユーザーのスロット②がどの版のものかは不明（Stage 36より前なら上のとおり復元不能。Stage 36以降のものなら、地図の編集または生成処理の版の違いで、別の原因）。旧版で保存した本物のスロットで、新版へ読み込んだときの表示は確認していない（`compat-check` は自動保存の往復のみ）。

## 判断直前のセーブ（`decision41.ts`）
- 自動モード（常に自動・遷都のみ手動・放置中のみ自動）でゲームが自分で決める**改元・政策の窓・遷都**の直前に、「判断が開いたままの状態」の写しを渡す（`noteDecision`、アプリが `setDecisionSink` で受ける。受け口がなければ何も起きない）。写しは判断を自動で取る**前**に作る（乱数は引かない）。
  - 改元: `startKaigen` が `openKaigen` した後、`settleKaigen(…, auto)` の前。
  - 政策の窓: `openWindow` が持ち点を付けた後、`autoResolve` の前。写しには手動の経路と同じ `policy.pending` を付ける。
  - 遷都: `due2200` で `unattended` のとき、`skip2200` の前。写しには `open2200` を適用する。
- アプリ（`app.ts keepDecisionPoint`）は写しを自動セーブポイントの新しい種別 `decision` として保存する（種別・判断の種類 `dk`・年）。世界ごとに**最新3件**だけを残し、50年ごと・遷都直後のセーブは押し出さない（`CP_DECISION_MAX`）。一覧には「判断直前(改元／政策介入／遷都)」と出る。
- 読込: 一覧の「読込」で、`prepareDecisionLoad` が自動モードを一時的に `priority`（介入優先）にして `resumeMode` に覚える。判断が開いているあいだ時間は止まり、決めると `stepMonthGen` の先頭の `resumeAfterDecision` が元のモードへ戻す。
- **検証**（`tests/unit/decision41.test.ts`、`tests/e2e/decision41.spec.ts`）: 受け口がなければ同一の進行／写しは生きたゲームとは別物／政策の窓: 開いたまま保存され、読み込むと時間が止まり、**自動と同じ選択で、止まらなかったゲームと完全に一致**（人口・路線・計画・辺・乱数・方針の記録）、**別の分野を選ぶと別の記録**／改元: 第1候補で一致、別の候補で別の元号、選んだ後に自動モードが戻る／遷都(1900): 開いた状態で保存され、二重に適用されない／保存先: 種別ごとの鍵、索引の読み戻し、最新3件だけが残り50年ごとのセーブは無傷／実アプリ: 自動で25年進めると判断直前のセーブが作られ、一覧から読み込むと政策の窓が開いて時間が止まり、決めると自動モードに戻る。
- **限界**: 政策の窓で「別の選択」をしても、点を使わない採択では世界は変わらず、記録だけが違う（採択が世界に効くのは持ち点を使った場合）。**写しを撮る頻度は判断ごと**（政策は10年ごと）で、1つあたり約1〜2.5MB（gzipで約1/10）。時間軸の分岐（別の時間軸として続ける）は既存の `assignBranch` に任せ、判断直前のセーブ専用の分岐は作っていない。Pixel 7a の実機では未確認。
