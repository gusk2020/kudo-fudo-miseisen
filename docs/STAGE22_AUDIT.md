# Stage 22 技術監査(新機能なし)

土台: PR #43(39a2f53)。この監査は `claude/stage22-audit`(PR #44、base は #43 のブランチ)。

## 一次監査の採否
| 指摘 | 結論 | 根拠 |
| --- | --- | --- |
| A 探索の重複 | **採用** | `seaField`/`nearestPortField`/`seaKmTo` が別々の手書きヒープを持ち、既存の `core/heap.ts` もあった。`sweep`(1本)+`MinHeap` に統一。候補・離島航路の結果は変更前と完全に同一(離島航路の長さのみ、同じ粗いマス内の隣島3件が 0km→15km)。海路候補の作成は 269ms→126ms |
| B 粗い格子の地理的妥当性 | **一部採用** | 行をまたぐ近傍参照(`i+di` の範囲検査なし)は事実 → `around()` で修正。粗い格子の「1セルでも海なら海」は**維持**: 角抜けを禁じると明石・関門が閉じ大阪〜広島などが到達不能になる(実測)。鹿児島〜福岡のように短めに出る組があるが、描画は陸を横切らない(既存テスト) |
| C キャッシュ | **問題なし(一部採用)** | 世界は構築後に不変(県庁所在地移転・2200年は世界を作り直す)ので古い候補は残らない。ただ港ごとの全海探索結果(約200KB×港数)が `seaMemo` に残り続けていたため、候補作成中だけ保持して解放 |
| D 候補の上限160 | **不採用** | 上限600と比べ、上位60件は完全一致(候補数125 vs 391、差は下位の裾のみ)。数値は変更せず。一方、**休止→再開の振動は事実**(同じ航路が約7年周期で休止・再開、34回/200年)。再開待ち15年・休止2回で再開しない、に変更 |
| E 描画 | **一部採用** | 起動直後のズームは Stage 21 以下(最大0.53秒 vs 0.62秒)。ゲーム開始後の初回表示で、海上経路の探索(`seaPath.search`)が目立ったため内側ループを軽量化(出力は完全に同一)。道路の線の再作成(Pixi の `buildLine`)は以前からの仕様で変更せず |
| F 保存・シミュレーション | **問題なし** | 2200年の再発火なし・取りこぼしなしはテスト済み。保存時の「月を一気に終える」処理は PR #43 で修正済み。保存サイズ 2.1MB(2005年)〜2.5MB(2100年)で増え方は緩やか。イベント数はほぼ一定(約1000〜1100) |

## 追加で見つけたもの
- 離島航路の「島どうし」で、同じ粗いマス内の2島は長さ 0km になっていた(→15km)。
- 休止→再開の振動が、毎年の開設枠を使い切り、新しい外洋航路が増えない副作用を生んでいた(下記バランス)。
