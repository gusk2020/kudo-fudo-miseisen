# Stage 3 データの出典・利用条件・容量（Issue #8 Stage A）

実在の日本の地形・海岸線・河川・都市位置・鉄道/道路の位置を、**アプリが起動時に読み込む形で**どこまで持っているかの記録。
サンドボックスから届く外部データは npm と raw.githubusercontent.com だけなので、他は GitHub Actions のランナーで取得して小さなファイルにしたものをコミットしている。

## 史実と架空モデルの区別
- **実在のもの**: 海岸線・標高・河川・府県の区分・都市の位置、鉄道/道路が通っている回廊（参考として）。
- **再構成**: 1950年の道路網・鉄道網。実在の路線台帳ではない（年表の最初の項目にそう書いてある）。路線の区間・規格・事業者は合成。
- **架空**: 人口の推移、需要、予算、路線番号、事業者名（「東京電鉄」「東日本旅客鉄道」などは一般的な名称を機械的に組み立てたもので、実在の会社の再現ではない）。
- **史実（平成世界線のみ・2026年まで）**: `src/sim/events.ts` の `real: true` の項目。国際事件は3世界線共通、国内の出来事は平成のみ史実、修文・正化は同じ世界情勢への**架空の対応**として別に書いてある。2027年以降は「予測モデル」。

## 容量と読み込み（実測）
起動時に読むデータの合計はおよそ 270 KB（上の3ファイル + 画面のコード）。OSM/MLIT など大きなデータは使っていない。
- 地形生成（5 km 格子 344×447、地形・河川・都市・府県割り）: Node で約 0.55 秒、ブラウザでは Worker 内で実行（画面は固まらない）。
- 1950年の道路・鉄道網の生成: 約 0.9 秒（10 ms 単位に分割して実行し、進捗を表示）。

## 将来の拡張（まだやっていない）
- 国土数値情報（鉄道/道路）や OSM はライセンス（ODbL・出典表示）とサイズの確認が要る。ランナーで取得して、日本の主要路線だけに間引いた版を作るのが現実的。
- 実在の河川の幅・湖の形などの精度向上。
