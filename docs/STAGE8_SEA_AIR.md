# Stage 8 — 琵琶湖横断・湖上航路・国際港湾と海路・地方空港と国際ハブ (Issue #22)

## 1. 琵琶湖の国道1号横断(`ceremony.ts` `lakeHops`)
- 開通の儀で湖の上に線を引くと、湖を渡る区間を見つけて、その前後の**湖岸の陸地**で道路を止める。湖面は1950年の技術(橋は1.5kmまで)では**湖上フェリー**、湖幅が技術の範囲なら**橋**で渡る。湖の上に道路のマスは作らない(テストで確認)。
- 湖の位置・回転・大きさを変えても、その時点の湖で判定する。湖の外側を回る線なら横断しない。
- 国道1号のUndo/Redo・やり直し・保存はそのまま(E2Eで確認)。

## 2. 湖上航路の発展(`ferry.ts` `reviewLakeFerries`)
- 湖の大きさで航路数に上限: `1 + 湖のマス数/20`(最大4)。琵琶湖(26マス)は2本、0.4倍の湖は1本。
- 候補の航路: 長軸(1950年からある)、**狭い所**(湖面が最も短い所。対岸が同じ陸地)、短軸、大きい湖だけの追加の横断航路。
- 1965年以降、既存の航路が混む(能力の50%以上)か湖岸の人口が60万人以上で、道路を造る意欲があり、港の整備費を負担できるときに次の航路を開く。休止中の航路も上限に数える。
- 橋への置き換え: 混んだ航路(60%以上)の湖面が、その年の技術で架けられる長さ以下なら**湖上大橋**を計画する。対象は混んだ航路そのもの、なければ狭い所。開通すると、その航路を通っていた路線(国道1号を含む)を橋に付け替え、フェリーは廃止する。
- 橋の区間は、フェリーや海峡連絡と同じく両岸の2マスだけを持つ(道路のマスはすべて陸地)。初期のStage 8で保存されたデータは、読み込み時に直す。
- 長期実行(seed 7)では、狭い所の橋が1970年までに、短軸の橋が2020年までにできた。湖上フェリーは長軸の1本が残る(全条件で同じ)。

## 3. 国際貿易港と海路(`hubs.ts`)
- **港湾は4段階**: 地方港湾 / 重要港湾 / 国際拠点港湾 / 国際戦略港湾。能力は 800 / 3,000 / 10,000 / 30,000(道路の貨物と同じ単位)。1950年は臨海都市の規模の順に、互いに12km以上離して置く。
- **需要**:
  - 都市の外国貿易 = 人口 ×(0.2+産業)× 製造業の誘因 × 時代の貿易指数(1973年=1)×(1+0.3×海路の選好)。
  - これを行ける港へ、港の規模と所要時間(道路と鉄道の速い方)で配分する。満杯の港は一部を次の港に譲る。
  - 港への輸送は道路・鉄道の貨物として網に載る(ある条件で網全体の貨物km +5%以上。テストで確認)。
  - 沿岸都市どうしの国内海運は、両方に港があるときだけで、距離が長いほど増える。港の容量にも縛られる。
- **航路**:
  - 行き先は抽象的な海外方面7つ(朝鮮半島、大陸東岸、沿海州、東南アジア、北米、豪州、欧州・中東)。
  - 港の取扱を、時代ごとの貿易の割合と、港が海のどちらを向いているかで分ける。
  - 重要港湾以上が、段階ごとの上限(2/4/7)まで定期航路を持つ。
  - 基準の半分を3年下回ると休止、さらに6年で廃止。回復すれば再開。
- **拡張・縮小**: 能力の85%以上が2年続き、海路の選好と予算があれば拡張(4〜6年。国際戦略港湾=コンテナ埠頭は1968年から)。2割以下が10年続けば縮小。地方港湾は15年ほぼ使われなければ閉港。臨海都市が育てば開港する。

## 4. 地方空港と国際ハブ空港(`hubs.ts`)
- **地方空港**:
  - 滑走路1,200m(能力2,000人/日)→2,000m(ジェット化、1960年〜、8,000)→2,500m(1975年〜、15,000)→3,000m(1985年〜、25,000)。
  - 開港の基準は Stage 3 と同じ人口の基準(空路の選好で早まる)。新たな空港は、既存の空港から60km以内には造らない(人口300万以上の都市を除く)。
  - 空港のない都市は、60km以内の隣の空港を使う(空港までの移動の分、空路の割合が下がる)。
- **国際ハブ空港**:
  - 3,000m以上、能力5万人/日。満杯が続けば第2滑走路・沖合展開などで1.7倍ずつ、最大4回増やせる(約42万人/日)。
  - 最初の1か所は1955年以降。国際旅客が増えると最大4か所。
  - 最大の地方空港との能力差は2倍以上(テストで確認)。
- **国際旅客**:
  - 人口 × 商業の誘因 × 国際旅行の指数(1990年=1)。船と飛行機の分担は時代で変わり、1960年代にジェットへ移る。
  - 国際空港までの距離で配分し、地上の移動は道路・鉄道に載せる。
  - 国際空港から2.5時間以上遠い都市に地元の空港があれば、国内線で乗り継ぐ(地上の長距離移動にしない)。
- **航空貨物**: 外国貿易の一部(1958年以降に増え、空路の選好で上がる)が国際空港へ流れる。
- **アクセス**:
  - ハブは市街から8〜25kmの海沿いの低地に置き、アクセス道路を実際の道路網として敷く。
  - 利用が能力の4割を超えると(1964年以降)アクセス鉄道を敷く。この道路・鉄道に空港の地上旅客が載る。
- **路線**:
  - 国内線は空港どうしの需要が大きい順(地方空港8路線、ハブ40路線まで)。国際線は国際旅客を方面に分ける(地方空港2、ハブ7まで)。
  - 休止・廃止は航路と同じ規則。地方空港は2000年以降、定期便がなく10年ほぼ空なら廃港。
- **費用・技術**:
  - 工費と工期は時代の段階(ジェット・コンテナ)と予算で決まる。
  - 橋・トンネルの技術規則(K)は長い構造物のための規則なので適用しない。
  - 港湾・空港は特別会計の扱いで、道路の予算は減らさない。

## 5. 交通手段間の競争と発展の歯止め
- **空路**: 距離、鉄道の速さ(Stage 3の式)に加え、時代(プロペラ機0.55倍・1960年代0.8倍・2012年以降LCC 1.1倍)と、空港の混雑(満杯なら1/混雑率)で割合が変わる。
- **海運**: 距離が短いと陸上輸送が勝つ。港が満杯なら他の港や陸上に回る。
- **地域への効果(上限つき)**:
  - 港の都市の産業 +0.12まで。成長率 +0.12%/年まで(国際拠点港湾以上・ハブ)。
  - 成長分は全国平均を差し引くので、**国全体の人口は増えず、地域の間で配分が変わる**だけ。最初の版では全国人口が2050年に+25%になったため、この形に直した。
  - Stage 7 の発展の歯止め(過密)もそのまま効く。

## 7. 地図・地図帳・年表
- レイヤー: **港湾**(四角。大きく濃いほど上位の港)、**空港**(白い飛行機=地方空港、大きな金色=国際ハブ)、**国際航路・空路**(青緑の破線=国際航路、橙の点線=国際線、白い細線=国内線)、**湖上フェリー**(凡例の切替)。
- 軽く描くための工夫:
  - 全国を表示しているときは、大きな港とハブの国際航路と、国内線の上位12本だけを描く。
  - 拡大すると全体を描く(国内線は上位30本)。軽量表示モードでは航路を描かない。
- 過去の年を選ぶと、その年に開いていた港・空港・航路を描く(閉港・廃止したものは消える)。
- 地図帳:
  - 港湾・空港の欄に、その年の数(段階別)、上位の港・空港の取扱・能力・航路・履歴(開港・拡張・縮小・閉港)、閉港・廃港の一覧を出す。
  - 「海と空の取扱」のグラフも出す。
- 年表: 「港湾・空港」の絞り込みを追加。航路の開設・休止は件数が多いので、年表が上限に達したときに先に間引く。
- 施設の履歴は年表とは別に、施設ごとに保存される。

## 8. 互換性・性能
- `sim.hubs` は省略可能。
  - 古いセーブは翌年の処理で作られる(空港はセーブの `airport` の年から、港は現在の都市から)。
  - 形の不正な `hubs` は読み込み時に捨てて作り直す(読み込みは拒否しない)。
  - JSONで保存して読み込んだ後も同じ結果になることを、単体テストで確認した。
- 性能(同じ環境・同じ時間帯で、Stage 8 着手前の版と比較):
  - Pixel 7 相当のエミュレーション(perf3、ソフトウェア描画): `pump` 1回の最大 518→**433〜448ms**、×20中の長いタスクの最大 1,420→**464〜1,274ms**(2回計測)。90秒で進んだ月数は 153→**168〜179**。保存サイズは 1.20→1.23MB。
  - 長期計算(node、1950〜2100、2条件同時): 実行時間 +3〜13%(55.7→62.8秒、54.0→55.7秒)。分析1回ごとに空港の利用圏を1度だけ作ることで、+20%から抑えた。
