## A. 鉄道重視で鉄道延長が止まる — 原因を特定して修正
### 調査（1800年開始・自動、固定シード7、`planRailGen` の関門ごとの計測）
- 年ごとの候補数は鉄道重視でも均衡でも十分あった（新線の候補 5件以上が全ての年）。方針ダイヤル `railBuild` の低下（1.00→0.06、経済循環）は両方に同じに起きており、差の原因ではなかった。
- **鉄道重視だけ**に、技術の関門（`techCheck`: その年の技術で掘れないトンネル長が要る山越え）の失敗が毎年 3〜4件（1830〜1890年に合計 21/64/80/80/49 件）。均衡は 0件。
- 計画は1年に経路探索を `MAX_RAIL_PATHFINDS = 5` 回しか試せない。上位に並ぶ、技術的にまだ建設できない同じ区間が毎年その枠を使い切り、建設できる下位の候補に順番が回らなかった（飢餓）。
### 修正
- 技術の関門に落ちた新線の候補（キー: 都市の組・セル）は、`RAIL_RETRY_YEARS = 6` 年は試さない（`sim.railFail` に年を記録）。技術が進めば再び試される。1800年開始ゲームだけ（`sim.rules1800`）。1950年開始は従来どおり（`railFail` は作られない。テスト済み）。
- 倍率・建設量の保証・方針の補正は入れていない。停止（需要・予算・地形・技術）は従来どおり。

## B. 海路重視の技術発展
- 船・港・渡船は1800年から実用（帆船）。これは関門にしない。
- 追加した段階（架空の未発明技術ではなく、船の更新）: 1830年基準の**蒸気船の定期航路**（渡船の速さ ×1.35）、1880年基準の**鋼鉄の汽船**（×1.8）。`rules1800.ts` の `shipGrade`。
- 海路重視の元号（`kairo`）の下で過ごした年数に比例して最大20年早まる（Stage 40 の方式と同じ。露出20年で最大、単調、開始年より前にならない、他の方針では動かない）。均衡でも基準年に開く。
- 実際の影響: `demand.ts` の `edgeSpeed` が渡船の速さを段階で変える（辺の `shipGrade`、1800年開始で毎年更新）。移動時間→需要・経路・計画の判断に効く。年表・地図帳には「船舶」の行として出る（実際に開いた年）。
- 完成済みの施設・技術は後の改元で戻らない（テストで 1800〜2050 を走査）。1950年開始は影響を受けない（`shipGrade` は付かない）。
- 未実装（正直に）: 港の取扱量の段階・運河・河川航行。港の容量（`hubs.ts`）は動かしていない。Stage 41 の海路世界の条件も扱っていない。

## 独立監査 #68 への対応
- `railFail` のキーを、都市の添字（`c.a/c.b`）から**都市ID**とセルに変更した（都市リストの並びが変わる #67 の動的な都市追加と衝突しない。並べ替えで同じ候補が同じキーになることをテスト）。
- 値は `[年, その年の技術で掘れる最長トンネル km]`。冷却は6年**かつ技術が同じ間だけ**で、より長いトンネルが掘れる年になれば待たずに再試行する（テスト）。旧セーブ（`railFail` なし）・1950年開始は冷却を一切使わない（テスト）。

- `shipGrade` は**船の速度だけ**を変える。港の容量・運河・河川航行は未実装（上記のとおり）。

## 優先4: 鉄道方針の逆転（調査結果・未解決・変更なし）
統合ブランチ（Stage 40＋海峡修正＋本PR）、1800年開始・自動、鉄道延長 km（開通済み、標準/地方線の内訳つき）。
| シード・年 | 鉄道重視 | 均衡 | 道路重視 |
|---|---|---|---|
| 7・1900 | **2815** | 2181 | 1712 |
| 7・1925 | 3011 | 2694 | 2461 |
| 7・1950 | 3117 | 3439 | 3464 |
| 11・1900 | **2451** | 2248 | 1523 |
| 11・1925 | 2724 | 2759 | 2240 |
| 11・1950 | 3419 | **3810** | 3041 |
- **確実**: 1900年までは、どちらのシードでも 鉄道重視 > 均衡 > 道路重視（A の修正前は鉄道重視が最少）。1925〜1950年に鉄道重視が追い抜かれる（シード7は道路重視が最大、シード11は均衡が最大）。以前に見た「道路重視 4472km（1950年）」は、船舶の更新(B)などの後は再現しない。順位は年とシードで入れ替わる不安定な量。
- 1925〜1950年の鉄道重視は新線が減る（シード7: 新線プロジェクト累計 33→31→27、均衡は 24→28→42）。方針ダイヤル `railBuild` は全方針で 1925年に 1.0 へ戻る（経済循環の好況）ので、ダイヤルの差ではない。
- **仮説（証明していない）**: 鉄道重視は 1900年までに需要の大きい回廊を先に建てたため、1925年以降は「鉄道で未充足の需要」（`planRailGen` の `unmet`、サービス水準 `svc > 0.65` で除外）が残っておらず、候補が尽きる。均衡・道路重視は後から同じ回廊を建てて追いつく。これは建設の上限や不具合ではなく、需要・財政・地形による停止として許容される動作。
- 検証していないこと: 候補数・`svc` の分布・資金の年次ログ（上の仮説を確かめるには必要）。固定ボーナスや倍率は足していない。さらに詰める場合は、1925〜1950年の候補生成の内訳を方針別に記録するのが次の手順。

## 優先3（PR #71 監査後）: 鉄道重視の1910〜1950年の停滞を計測 — 仮説を訂正、修正案は採用せず
条件: 固定シード7、1800年開始・自動、`tests/study/rail66.test.ts`（`STUDY=1 SEED=7 ERA=0|1|2`、CIでは走らない）。`planRailGen` の「黙って見送る出口」を数える一時パッチは `tests/study/rail66-counters.patch`（コードには入れていない）。鉄道延長 km（1900 / 1925 / 1950）: 均衡(ERA0) 2181 / 2694 / 3439、道路重視(ERA1) 1756 / 2620 / 3077、鉄道重視(ERA2) 2815 / 3011 / 3117。
- **上の仮説（需要が尽きて候補が無くなる）は誤り**。鉄道重視でも未充足の都市の組（40〜260km、鉄道・道路のサービス水準0.65以下）は1925〜1950年に約294組、その未充足需要の合計は 49k→126k と増え続け、道路重視（52k→124k）とほぼ同じ。`railBuild` は全方針で1910〜1950年に 1.00。
- **確定した機構**: 計画は年に経路探索を `MAX_RAIL_PATHFINDS = 5` 回しか使えない。鉄道重視では1915年以降、この5回を毎年「技術未達（`tech`、約2件/年）」と「新設分が15km未満で見送り（`short`、約3件/年）」が使い切り、新線の構想は5年に0〜1件。新線を作れない原因は需要でも予算（`afford` の見送りは0）でもなく、**探索枠の占有**。#66 A（技術未達だけの占有を待機で解消）と同じ型の問題が、`short` に残っている。均衡・道路重視は、上位の候補が `short` や `tech` になりにくく、枠が建設できる候補に回る。
- 試して**採用しなかった**修正:
  1. 待機中（`cooling`）の候補を上位25件の切り出しの前に除く: 全ての数値が**バイトまで同じ**（待機中の候補は枠を塞いでいない）。
  2. `short` の見送りにも `railFail` の待機を付ける: 鉄道重視の停滞は直らず（1925→1950年は 2988→3439）、均衡は 2181/2694/3439 → 2365/2961/4102、道路重視は 1756/2620/3077 → 1375/2327/3706 と、承認済みの他の方針の数値と順位が大きく動く（1950年は道路重視が鉄道重視を上回る）。他方針に大きく波及する長期バランスの変更になるため、単独の修正としては採用せず、コードは変えていない（`planning.ts` は無変更）。
- 次の手順（未実装、独立した作業）: 経路探索の枠を**候補の種類で分ける**（探索なしで分かる `short` 候補、例えば両都市が既に鉄道で結ばれている組を事前に除く）設計を、全方針・複数シードで測る。#66 A の鉄道延長の数値（`rail66.test.ts` の 1343/2181）を使うテストは、動かすなら理由を記録して更新する。

## 優先3の続き: 経路探索の目詰まりに「短い探索結果の記憶」を採用（branch `claude/issue66-pathfind-budget`、base `claude/issue67-stage2`）
### 設計の比較（実験用スイッチ。11シード × 方針3 × 案、1800→1950、鉄道延長 km）
探索の前に分かる条件と後にしか分からない条件: 前に分かるのは種類・距離（40〜260km）・サービス水準・待機中かどうか。**後にしか分からない**のは経路があるか・新設分が15km以上か・技術の関門・予算（`afford`）。新設分の「短さ」は探索の結果なので、**事前に確定扱いせず**、「同じ組・同じ鉄道網なら結果は同じ」という性質だけを使って、鉄道網が変わるか待機が終わるまで繰り返さないことにした。

|---|---|---|

| **A（採用）** | 「新設15km未満」の結果を、鉄道網の版（鉄道辺の数と長さ）が変わるまで最大6年記憶。1800年開始のみ | 伸び **+830 km、停滞 0/11**、1950年 均衡3837・道路4092・鉄道4058。探索回数は減り（実験版12年待機: 472→413回/ゲーム）、CPU時間は同じ（30.0→29.7秒） |
