## Stage 1 基盤の確認結果（良い点）
- 座標API: `GeoMap.toWorld/toGeo` は変形・回転・拡縮込みの往復誤差 <0.01°（テスト済み）。道路は world km＋島ID で保持できる。
- 地図確定後は決定論: 同一 state → 同一 `terrain.hash`。Node(Vitest)とブラウザ(Chromium)で hash 一致（62e65ffd）。
- 安定ID: 島/県/都市/河川/湖/山脈(`isl.* pref.* city.* riv.NNN lake.biwa`)は路線IDと独立。`cell.*` は格子定義(x0,y0,cell)に依存し、路線IDとは分離済み（Issue #3-6と整合）。
- 東京府は 99 セル（5km格子で道路1本＋腐道1本を置くのに十分）。都市60（県庁49含む）。

## 実装前に決めるべき項目（重要度順）
1. **地図ロック（高）**: 現状 `finalized` は編集で黙って解除される。道路・シミュ状態が存在する間は地図編集を禁止し、シミュ保存に `terrain.hash`＋`state` ハッシュを持たせ、不一致なら道路を読み込まず警告する（`parseState` は壊れた地図を既定値に黙って置換するため、そのまま使うと道路が無関係な地図に載る）。
2. **セーブ構造（高）**: 現 `ProjectState`(schemaVersion 1) は地図専用で、未知のキーを捨てる。`{ schemaVersion:2, map: ProjectState, sim: {schemaVersion, ...} }` の包み構造にして v1 を `map` に移行する migration を用意。`sim` は乱数状態・ゲーム内時刻・最終保存の実時刻を持つ。
3. **地形の端末間再現（中）**: terrain は保存せず毎回再生成。Math.sin/exp/pow の実装差で Safari 等では hash がずれ得る（V8同士のみ検証済み）。確定時に terrain 配列（圧縮）を IndexedDB に保存し、再生成ではなく保存値を使うか、hash 不一致で警告する。
3. **地形クエリAPI不足（中）**: `GeoMap` は `cellId` のみ。道路には「地点の標高・勾配・陸/海/湖・県・河川交差」の問い合わせが必要（`TerrainResult` から薄く作れる）。
4. **需要の元データ不足（中）**: 人口は `pop` が非県庁の約11都市にしかない（県庁49は未格納）。産業は無し。→ `build_data.py` で全都市に `pop_max` を格納し、セル人口/産業は「合成値」として明示して生成（実在統計と偽らない）。
5. **描画の更新方式（中）**: Renderer は変更ごとに全レイヤーを再構築する。Stage 2 の時間経過で毎ティック全再構築しないよう、道路・計画線は専用の動的レイヤー（差分更新）にする。
6. **島間の接続（低）**: 海峡をまたぐ道路（橋・フェリー）を最小スライスで許すか未定。5km格子以下の橋梁を捏造しない方針なので、最初は「島内のみ」を推奨。沖縄は九州の付属パーツで九州とは海で隔たる。

## 受入条件との対応
- 決定論・保存再開・無効データ耐性: Stage 1 の `parseState`（例外を投げない）と `mulberry32` を流用可。シミュは整数ティックと保存可能な乱数状態で実装。
- 長期離席: 復帰時に上限付き集約計算（ティック上限を設ける）。
- 開通の儀（手描き→ノード/エッジへのスナップ）: 空間索引が未実装。ノード＝都市/交差点/峠/端点の分離データ構造とともに新規実装。
- stacked PR: ベースを `claude/stage1-map-generator` とする新ブランチ（例 `claude/stage2-roads`）を推奨。main へはマージしない。
