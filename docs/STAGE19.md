# Stage 19: 設定タブ・地図で選ぶ首都等・元号リスト・都市名の重なり防止・海岸線判定の修正

## 1. 設定のタブ
元号・首都・副首都・皇居の4つの小さなタブを1行に並べる(スマホ幅412pxで4等分、高さ40px)。通常は設定欄を開かない。タブを押すとその設定欄だけが開き、別のタブを押すと前の欄は閉じる。「✕ 設定欄を閉じる」またはもう一度そのタブを押すと閉じる。道路を引くなど他の道具を選んでも閉じる。元号の欄には「地図の表示(道路図/地形図)」も置いた。

## 2. 首都・副首都・皇居の選び方(共通)
タブを押すと「A 府県から選ぶ」「B 地図から選ぶ」。
- A: 従来の地域ブロック別の49府県リスト。県庁所在地が位置になる(従来どおりの結果)。選ぶと、その席に地図で指定した点があれば消える。
- B: 地図をタップ。陸地の点で、府県が決まる点だけ受け付ける(海・対象外は「陸地の点をタップしてください」で拒否)。タップは**候補**(橙の十字+「候補」)として出るだけで、「決定」で確定、「取り消し」で破棄(誤タップでは何も変わらない)。首都と副首都が同じ府県になる選択は拒否。タップした点そのものを `capitalPos / subPos / palacePos`(世界座標)として保持し、保存・読込で復元する。選択中は地図タップだけが働き、道路・地形の編集は動かない。「県庁所在地に戻す」で点を消す。
画面には「首都: 愛知県(地図で指定 東経…° 北緯…°)」を出す。

## 3. 指定した点とシミュレーション
- 府県順位の「所属府県」は指定点の府県。3地点の重心だけに、実際の座標(緯度経度)を使う(`potentialOrder(... at)`)。県庁所在地のままなら従来と同じ順位。
- 首都・副首都の引力(`recon.coreness`)と衛星都市の適性(`city17.suitability` の席への近さ)は指定点から測る。
- 国道1号の開通の儀は従来どおり首都・副首都の県庁所在地の都市の間(都市や人口は消えず、全国人口は増えない)。
- 旧セーブ・旧ゲームには点がなく、従来値(県庁所在地)のまま。新規ゲームの順位記録は `pot17.c19`、改元の再割当も同じ座標を使う。

## 4. 元号の一覧
タイル状のボタンをやめ、府県リストと同じ形式にした。最初の元号は1つのリスト(見出し=グループ、1行=1候補「元号名 ─ 主な政策効果」)、改元の画面は見出し付きの1行ボタン。グループは候補の方針そのもの: 道路系(道路重視)・鉄道系(鉄道重視)・海路系(海路重視)・空路系(空路重視)・均衡系(均衡)。候補のないグループは出ない。1945年の14候補は5グループすべてに入る。1989年は 平成=均衡系・修文=道路系・正化=鉄道系。元号名・効果・改元制度は不変(Stage 18 の海路・空路の建設規則も不変)。選択中の元号は「選択中: …」で常に表示し、改元時は「現在の元号」を出す。

## 5. 都市名の重なり防止(`render/cityNames.ts`)
成長した衛星都市の名前は、大きい順(首都・副首都が先)に、丸の右・左・上・下のうち最初に何とも重ならない側へ置く。重ならない対象は、すでに置いた名前、すべての丸、地図の底の層が描く県庁所在地の名前。置けない都市は名前を出さない(丸は残る)。表示数の上限は縮小時0、ズーム0.55〜1で10、1〜2で24、2以上で60。計算は再描画のときだけ(地図移動中は毎フレームではない)で、200都市でも数ミリ秒。表示の条件(7万人・1.6倍、5万人未満で非表示)は不変。地図帳の「都市の誕生」に名前・年・人口が出る。

## 6. 海岸線の判定
Stage 18 のセル数による判定は、生成された県域と5kmの格子の影響で、奈良を太平洋側、山形を側なしと誤った。Stage 19 は実際の海岸を事実の表(`PREF_COAST`)で持つ。分類: 日本海側のみ / 太平洋側のみ(瀬戸内海・大阪湾・有明海・東シナ海を含む) / 両側(青森・北海道の札幌と函館・兵庫・山口・福岡・佐賀・長崎。補正なし) / 内陸(栃木・群馬・埼玉・山梨・長野・岐阜・滋賀・奈良。補正なし)。格子の数え上げは地形との照合のテストにだけ残した。奈良=内陸、山形=日本海側、東京・大阪=太平洋側、京都=日本海側(京都の海岸は日本海のみ)。2つ上げるルール(一極集中17〜49位、地方分散11〜49位のランダム部分だけ)は不変。
